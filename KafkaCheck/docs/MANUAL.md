# 📘 Руководство пользователя KafkaCheck

Эта инструкция поможет вам запустить проект, протестировать его работу и научиться пользоваться Kafka UI.

## 📋 Предварительные требования

Перед началом убедитесь, что у вас установлены:
- **Docker** и **Docker Compose**
- **Go** (версии 1.21 или выше)
- **Make** (для Windows можно использовать Git Bash или WSL, либо запускать команды вручную)

---

## 🚀 Шаг 1: Запуск Kafka

Мы используем режим **KRaft** (без Zookeeper), так как это современный стандарт.

1. Откройте терминал в папке проекта.
2. Запустите Kafka:
   ```bash
   make kafka-up
   ```
   *Если вы не используете make:* `docker-compose up -d`

3. **Важно:** Подождите примерно 30-40 секунд, пока брокеры инициализируются и выберут контроллер.

---

## 🧪 Шаг 2: Запуск Тестового Сценария

Приложение `KafkaCheck` работает в режиме "демонстрации": оно само создает сообщения, отправляет их и тут же читает.

1. Запустите приложение:
   ```bash
   make run
   ```
   *Если вы не используете make:* `go run ./cmd/server`

2. **Что должно произойти:**
   - В консоли появятся логи подключения к 3 брокерам (`[OK] localhost:9092`...)
   - **Producer** отправит 10 тестовых сообщений.
   - **Consumer** прочитает эти сообщения.
   - Вы увидите логи `[SEND]` и `[RECV]`.
   - Приложение покажет статистику и завершится.

   **Пример успешного вывода:**
   ```text
   Starting KafkaCheck...
   Kafka brokers are available
   Producer initialized
   Consumer initialized
   [SEND] id=msg-1 content="Test message #1"
   [RECV] id=msg-1 content="Test message #1" time=22:30:45
   ...
   Application stopped
   ```

## 📊 Шаг 3: Работа с Kafka UI

Kafka UI — это веб-интерфейс для управления кластером.

1. Откройте браузер и перейдите по адресу: [http://localhost:8080](http://localhost:8080)

### Что посмотреть:

#### 1. Topics (Топики)
- Перейдите в раздел **Topics**.
- Найдите топик `test_topic` (он создается автоматически).
- Вы увидите количество партиций (по умолчанию 3) и репликацию.

#### 2. Messages (Сообщения)
- Кликните на имя топика `test_topic`.
- Перейдите на вкладку **Messages**.
- Вы увидите отправленные сообщения. Можно кликнуть на любое сообщение, чтобы увидеть его содержимое (JSON/Protobuf значения).
  > *Примечание: Так как мы используем Protobuf сериализацию, данные в Kafka UI могут выглядеть как байты, если не настроена схема. Это нормально.*

#### 3. Consumers (Консьюмеры)
- Перейдите в раздел **Consumers**.
- Найдите группу `kafkacheck-group`.
- Здесь показано, насколько "здоров" консьюмер и есть ли у него отставание (Lag).

#### 4. Отправка сообщений вручную (Produce Message)
Вы можете отправить сообщение прямо из интерфейса, чтобы проверить, что Consumer его прочитает:
1. Зайдите в раздел **Topics**.
2. Кликните на топик `test_topic`.
3. Нажмите кнопку **Produce Message** (обычно вверху справа).
4. В поле **Value** введите текст (например: `Привет из UI!`).
5. Нажмите **Produce Message** внизу.
6. Если приложение (`make run`) запущено, вы увидите в консоли, что Consumer прочитал ваше сообщение:
   `[RECV] ... Привет из UI! ...`

#### 5. Отправка сообщений из терминала (Console Producer)

Вы можете отправлять сообщения из своего привычного терминала (PowerShell, CMD, Bash), не устанавливая Kafka локально.

Для этого используйте команду-обертку. Она запускает утилиту отправки **внутри** контейнера, но привязывает к ней ваш ввод/вывод. Вы остаетесь в своем терминале.

**Команда:**

```bash
docker exec -it kafka1 kafka-console-producer --bootstrap-server kafka1:19092 --topic test_topic
```

После запуска появится пустая строка (или знак `>`).
1. Введите сообщение и нажмите `Enter`.
2. Введите еще одно.
3. Чтобы выйти, нажмите `Ctrl+C`.

*Почему так?*
Чтобы запустить `kafka-console-producer` без Docker, вам пришлось бы устанавливать Java и скачивать бинарные файлы Kafka на Windows. Использование `docker exec` позволяет избежать загрязнения системы лишним софтом.

## 🛠 Ручное тестирование (Эксперименты)

Вы можете менять настройки в `configs/config.yaml`, чтобы увидеть, как это влияет на работу Kafka.

### Сценарий 1: Отключение брокера
1. Запустите `make run` в бесконечном цикле (увеличьте `messages_count` в конфиге или поставьте паузу побольше).
2. "Убейте" один из брокеров:
   ```bash
   docker stop kafka2
   ```
3. Посмотрите логи приложения. Благодаря репликации (`required_acks: WaitForAll`), приложение должно продолжить работу (возможно с небольшой задержкой), переключившись на другие брокеры.

### Сценарий 2: Чтение старых сообщений
1. В `configs/config.yaml` измените:
   ```yaml
   consumer:
     initial_offset: "oldest"
   ```
2. Запустите `make run`. Сonusmer прочитает ВСЕ сообщения, которые когда-либо были отправлены в этот топик (и еще не удалены политикой retention).

### Сценарий 3: Kafka не доступна
1. Остановите Kafka: `make kafka-down`.
2. Запустите `make run`.
3. Приложение будет пытаться подключиться в течение 60 секунд (настройка `kafka_ready_timeout`), а затем выдаст ошибку.

## ❓ Устранение неполадок

**Ошибка: `dial tcp ... connectex: No connection...`**
- Kafka еще не запустилась. Подождите немного и попробуйте снова.
- Проверьте, что контейнеры работают: `docker-compose ps`.

**Ошибка: `kafka not ready: timeout waiting for brokers`**
- Возможно, Docker заблокирован фаерволом или не хватает ресурсов.
- Попробуйте сбросить данные: `make kafka-reset`, затем `make kafka-up`.

**Нет сообщений в Kafka UI**
- Проверьте, что вы выбрали правильный кластер в меню слева.
- Убедитесь, что приложение успешно отработало (Exit code 0).

## 📚 Полезные команды Make

| Команда | Действие |
|---------|----------|
| `make kafka-up` | Запуск Kafka (KRaft) |
| `make kafka-down` | Остановка Kafka |
| `make kafka-reset` | Остановка и удаление всех данных (чистый старт) |
| `make run` | Сборка и запуск приложения |
| `make kafka-logs` | Просмотр логов брокеров |
